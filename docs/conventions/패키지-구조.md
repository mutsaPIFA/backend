# 패키지 구조 & 의존성 컨벤션

> **현재 규칙** 문서. 시점 기록(왜 이렇게 정했는지, 당시 대안)은 [`../specs/2026-08-13-backend-skeleton-design.md`](../specs/2026-08-13-backend-skeleton-design.md).

base package: `com.mutsapifa.mcmmuse`

## 디렉토리 구조

```
src/main/java/com/mutsapifa/mcmmuse/
├── McmMuseApplication.java
│
├── auth/                      # Bounded Context (BC)
│   ├── domain/                #   @Entity, Enum, 도메인 예외, 값객체
│   │   └── exception/
│   ├── application/           #   Service(유스케이스)
│   │   └── dto/               #     서비스 ↔ 컨트롤러 내부 DTO
│   ├── infrastructure/        #   Repository, 외부 시스템 어댑터
│   └── presentation/          #   Controller
│       └── dto/               #     Request/Response DTO (외부 노출)
│
├── catalog/                   # 위와 동일한 4계층
├── closet/
├── styling/
│
└── shared/                    # BC 아님 — 전역 공용
    ├── config/                #   SecurityConfig, CORS, JwtAuthFilter
    ├── exception/             #   GlobalExceptionHandler, ApiError
    ├── vocab/                 #   controlled vocabulary enum (Category·Color·Material·ItemMood·Source)
    │                          #     계약 "공통 타입"과 1:1 — 여러 BC가 공유하므로 shared에 둔다
    ├── storage/               #   StorageService(interface) + Local/S3
    └── aiclient/              #   AI 서비스 HTTP 클라이언트 + Mock 구현
```

## Bounded Context 목록

| BC | 책임 | 영속 엔티티 | API 정의서 § |
|----|------|------------|-------------|
| `auth` | 인증·계정 | `User` | §1 인증 · 사용자 |
| `catalog` | MCM 상품 카탈로그·시드 적재 | `McmProduct` | §2 MCM 제품 카탈로그 |
| `closet` | 내 옷장·스캔 | `ClosetItem` | §3 옷장 |
| `styling` | 스타일 DNA·추천·무드·코디·룩 | `Mood`, `Look` | §4 스타일링 |
| `shared` | (BC 아님) 전역 공용 | — | — |

**왜 `catalog`인가** — `home`은 화면 이름이고 도메인 이름이 아니다. 화면 번호·이름은 이미 한 번 통째로 바뀌었으므로 패키지를 화면에 묶으면 이름이 거짓말이 된다.

**왜 추천이 `styling`인가** — `POST /style-dna`·`POST /recommendations`는 입력만 옷장이고 출력은 MCM 제품 추천이다. `closet`에 두면 `ClosetItem`과 `Recommendation`이 한 BC에 섞인다.

**왜 `profile` BC가 없는가** — 현재 프로필에 담을 것이 닉네임뿐이라 엔티티가 0개다. `GET /me`는 `auth`에 둔다. 프로필 이미지·취향 설정이 붙는 시점에 분리한다.

## DDD 4계층

| 계층 | 책임 | 담는 것 |
|---|---|---|
| `domain` | 비즈니스 룰 | `@Entity`, Enum, 도메인 예외, 값객체 |
| `application` | 유스케이스 조율 | Service, 내부 DTO |
| `infrastructure` | 외부 시스템 연결 | Repository, 외부 API 클라이언트 |
| `presentation` | 외부와의 인터페이스 | Controller, Request/Response DTO |

### 계층 의존 방향 (단방향)

```
presentation ──┐
               ├──► application ──► domain
infrastructure ┘
```

- **`domain`은 어떤 외곽 계층도 import하지 않는다.** JPA 어노테이션은 허용(DDD-Lite — 도메인 모델과 JPA 엔티티를 분리하지 않음).
- `application`은 `domain`만 알면 된다. 단 **Spring Data Repository 직접 주입은 허용**(실용성).
- `infrastructure`·`presentation`은 `application`·`domain`을 알 수 있다.

## BC 간 의존

강제 룰은 없다(모놀리식 단일 jar). 다만 **사이클을 만들지 않는다.**

예상 방향 — 이 방향만 허용:

```
styling ──► closet ──► catalog
   └──────────────────────┘
```

- `closet → catalog` : 카탈로그 MCM을 옷장에 담기(`POST /closet-items {mcmProductId}`)
- `styling → closet` : 코디 재료로 옷장 아이템 읽기
- `styling → catalog` : `seedMcmProductId` 검증, 추천 제품 재조회

**역방향(`catalog → closet` 등)은 만들지 않는다.** 필요해지면 설계를 다시 본다.

### 한 가지만 강제

**BC 간 엔티티 연관관계 금지 — 참조는 id 값(Long)으로만.** `ClosetItem.userId`, `Look.mcmProductId`처럼 다른 BC 리소스는 `Long` id 필드로 들고, `@ManyToOne` 등 JPA 연관은 **같은 BC 안에서만** 건다. DB FK는 Flyway 스키마가 이미 보장하므로 무결성은 잃지 않는다. (이유: 엔티티 연관이 BC를 가로지르면 BC 경계가 코드에서 사라지고, 조회 한 번에 옆 BC 테이블이 딸려온다)

**`shared`는 어떤 BC도 import하지 않는다.** `shared/config/SecurityConfig`가 `auth/application/AuthService`를 참조하면 의존 그래프가 꼬인다.

## 파일 위치 가이드

| 만드는 것 | 위치 |
|---|---|
| `@Entity` 클래스 | `{bc}/domain/` |
| Enum (도메인 의미) | `{bc}/domain/` |
| `*Service` | `{bc}/application/` |
| `*Repository` (Spring Data) | `{bc}/infrastructure/` |
| `*Controller` | `{bc}/presentation/` |
| Request/Response DTO (외부 노출) | `{bc}/presentation/dto/` |
| 내부 DTO (서비스 ↔ 컨트롤러) | `{bc}/application/dto/` |
| BC 전용 예외 | `{bc}/domain/exception/` |
| 전역 설정·예외·스토리지·AI클라이언트 | `shared/` |

## 안 하는 것

- ❌ `domain`에 `@Service`, `@Controller` 등 Spring 어노테이션
- ❌ `domain`이 `application`/`infrastructure`/`presentation` import
- ❌ `shared`가 BC 패키지 import
- ❌ 같은 이름의 클래스를 여러 BC에 두고 `@Component` (Bean 이름 충돌)
- ❌ 패키지 이름에 화면 이름 쓰기 (`home`, `mypage` 등)

## 새 BC 추가

```bash
mkdir -p src/main/java/com/mutsapifa/mcmmuse/{bc}/{domain/exception,application/dto,infrastructure,presentation/dto}
```

`domain/` 엔티티 → `application/` 서비스 → `infrastructure/` 리포지토리 → `presentation/` 컨트롤러 순으로 채운다.
